Key the means-tested deduction scales on net income, and drop a false limitation

The phase-out scales were applied to GROSS income, and the module documented the
result as an acknowledged, unsolved circularity. Both halves of that were wrong.
Test count rises from 199 to 201.

The column is Reineinkommen, which is net income

Keying on gross understated the deduction for exactly the households it exists for:
a household with more deductions has LOWER net income, and the scale allows it
more. Measured effects:

    SH  gross 20,000, +1,500 premiums    3,225 -> 3,525
    FR  gross 25,000                     3,100 -> 3,500
    FR  gross 30,000                     2,100 -> 2,500

Every differing scale moves UP, which is the direction that makes a means-tested
deduction coherent.

There was no circularity to begin with

The base is income minus the OTHER deductions, excluding the means-tested deduction
itself. Subtracting that too would lower the base, raising the deduction, lowering
the base again -- a loop that exists only if you define the base that way. Defined
as "the income remaining after the other deductions" it is a plain single pass.

That distinction is the point of the change: it is the difference between a
definition and a fixed-point search, and the module had recorded the wrong one as a
limitation. `means_tested_deduction_does_not_feed_its_own_base` asserts it by
assessing the same household twice and requiring identical answers, so a future
edit that reintroduces the feedback is caught.

`means_tested` and `means_tested_scale_for` now take the scale base as a parameter
rather than reading `household.gross_income` internally, so the gross/net
distinction cannot be silently collapsed by a later edit. `means_tested_scale`
remains as a convenience for a household that declares nothing, where net income is
gross income.

Tests (tests/deduction_engine.rs, 2 new)

  means_tested_deduction_does_not_feed_its_own_base
  means_tested_scales_use_net_income_for_every_canton

The second sweeps every canton holding a scale and asserts the direction, while
deliberately SKIPPING the capped regime: Valais allows CHF 21,250 against a
CHF 15,000 income, so there the base has no observable effect and asserting one
would be asserting a coincidence. Four cantons are exercised, and the test fails if
fewer than three are, so it cannot quietly become vacuous.

Documentation

SWISS_TAX_DATA.md's phase-out section is rewritten: it records the mis-keyed base,
the numeric effects, and why the "circularity" was a mistake rather than a
limitation. The module's own gaps list no longer claims it as unsolved.

Verified: 201 tests pass, clippy unchanged at 9 pre-existing warnings.
