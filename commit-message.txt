Add two-level Swiss tax model with canton registry and ESTV scale import

Implements the two-level Swiss tax model: a shared federal layer, a 26-canton
registry, and cantonal tax as base scale x Steuerfuss. Wires --canton honestly,
and adds an importer for ESTV "Tarife" exports. Test count rises from 91 to 141.

Canton registry (src/cantons.rs)

All 26 cantons with official codes, names and capitals, plus from_code parsing.
CantonTaxData carries every numeric field as an Option paired with a Provenance
(Official { source, year } / UserProvided / NotSourced). There is deliberately
no fallback: an unsourced canton returns CantonTaxError::NotSourced naming what
is missing, and never substitutes another canton's rates or an estimate.
Cantonal tax varies by roughly a factor of three across Switzerland, so a
substituted multiplier would silently change every recommendation while still
looking authoritative.

Steuerfuss data (src/canton_steuerfuss_data.rs)

832 rows -- 26 cantons x 32 years (1995-2026) -- generated by
tools/generate_steuerfuss.py from the official ESTV workbook
"Steuerfuesse in den Kantonshauptorten" (natural persons). The generator
preserves source exceptions rather than guessing, and distinguishes three cases
that were previously conflated:

  - a plain multiplier
  - a blank cell (the multiplier does not apply, e.g. no church tax)
  - an unparsed cell (a footnote marker like "3)", or a figure expressed
    relative to another tax like "88% 7)"), whose raw text is retained

Collapsing the last two would make "no church tax here" indistinguishable from
"we could not read this figure". The test
documented_source_exceptions_are_preserved fails if a future regeneration
silently turns an exception into a number.

Cantonal tax calculation

cantonal_tax_from_scale() implements the composition rule on explicit inputs so
it is testable without any canton's scale being loaded:

    cantonal_tax = simple_tax(taxable_income, scale) x (cantonal + municipal)

Multipliers use the ESTV factor form, so 0.98 means 98%. Income splitting is
supported (divide income by the factor, apply the scale, multiply back): on a
linear scale splitting is provably neutral, on a progressive scale it strictly
reduces tax, and both properties are asserted.

ESTV scale import (tools/import_estv_scales.py)

Parses an ESTV "Tarife" export (.xlsx) into src/estv_scales_data.rs. The format
expresses the tariff as band WIDTHS ("Fuer die naechsten CHF"), not thresholds;
the importer accumulates widths into thresholds, which is exact for the marginal
structure. It reads every canton present in a file, not just one.

Aargau is wired end to end as the first canton beyond Bern: ESTV-imported scale,
Steuerfuss from the ESTV workbook, and Splittingfaktor 2.0. At CHF 100,000
taxable the model returns CHF 9,869.76, independently hand-checked
(assessable 50,000 -> simple tax 2,384 -> x2 for splitting -> x2.07 total
Steuerfuss), i.e. 9.87% of income.

--canton behaviour

Previously --canton was accepted, defaulted to "ZH", and silently ignored, so
--canton ZH returned Bern numbers. It now:

  - omitted          -> uses Bern, the canton with a complete table, and says so
  - known and priced -> uses that canton's scale
  - known, unpriced  -> exits 2 naming what is missing, with two workarounds,
                        and prints no projection
  - unknown code     -> rejected as a code, listing the valid ones

--custom-tax-rate bypasses canton resolution entirely, since an observed
personal rate needs no cantonal data.

Federal layer

src/federal_tax.rs holds the federal tariff structure and arithmetic. The
values are marked FEDERAL_TARIFF_IS_VERIFIED = false: the encoded table has a
non-monotonic segment (a decreasing marginal rate between 72,500 and 103,600),
which no progressive tariff can have, and no authoritative source has been
available to correct it. monotonicity_violations() reports the bad brackets and
tariff_flagged_verified_must_be_monotonic fails if the flag is raised without
fixing the data. New tests pin monotonicity of thresholds, the doubling of the
married tariff, and the published effective-rate range.

Note that Tarif Art. 42 - Abs. 1 in this repository is canton Bern's tariff, not
a federal one.

Published reference cross-check (tests/published_tax_reference.rs)

Pins five published reference points for Zuerich, Schwyz and Bern (ESTV
Steuerrechner, Steuerjahr 2025, via finpension.ch). Two findings:

  - The cantonal ordering is income-dependent: Schwyz is NOT cheapest at
    CHF 25,000, Zuerich is. A fixed ranking assumption is wrong at the low end.
  - Bern's shipped table under-taxes by 5.7 to 12.4 percentage points, and it
    has no entries above CHF 200,000 so lookup_tax_rate clamps, returning an
    identical 24.73% at both CHF 250,000 and CHF 500,000. Documented in
    SWISS_TAX_DATA.md; Bern output above roughly CHF 200,000 taxable should not
    be trusted.

GPL-3.0 headers

Adds the GPL-3.0 header to all 23 .rs files via tools/add_license_header.py,
which is idempotent and skips target/, .git/ and .dsh/. The header uses //
rather than //! so it stays independent of the existing //! module docs and
#![...] inner attributes. The repository LICENSE is already GPL-3.0, so this
makes the source headers consistent with terms the project already declares.

Documentation

SWISS_TAX_DATA.md records the provenance of every number, what is still missing,
the exact export format needed, and the two parsing traps encountered: the
thousands separator is U+2019 rather than ASCII, and a naive token regex
silently discards every thousands-separated value.

Still open

Only Bern and Aargau are priceable. The other 24 cantons fail loudly by design
until their ESTV scale exports are supplied; the importer reads every canton
present in a file, so further exports are a data step rather than new code. The
federal tariff values remain unverified for the reason above.

Verified: 141 tests pass across 11 targets, cargo doc --lib clean under
-D warnings, no new clippy warnings (8 pre-existing remain).
