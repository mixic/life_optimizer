Import ESTV tax scales for seven more cantons

Adds cantonal base scales for BS, FR, GE, LU, SH, SO and ZH from ESTV
"Tarife" exports, and reworks the importer for the two marital structures
those exports revealed. Six cantons now price end to end; test count rises
from 145 to 150.

Coverage

Priceable: AG, BS, LU, SH, SO, ZH (six), plus Bern via its legacy standalone
table. Previously only Bern and Aargau could produce a figure.

Imported but deliberately not priceable, because the canton has no usable
multiplier:

  GE  scale imported, but its Steuerfuss cell reads "148.5%9)" with footnote 9:
      a 12% rebate applies, so the printed figure is not the effective rate
  FR  scale imported, but its Steuerfuss cell is blank

Both refuse and name the multiplier, not the scale, as missing.

Marital treatment is expressed in two incompatible ways

The exports forced this distinction, which a single-shape model would have got
wrong. A canton either:

  * publishes ONE shared scale (Steuersubjekt = Alle) and expresses the marital
    difference through a splitting factor -- AG 2.0, SH 1.9, SO 1.9; or
  * publishes SEPARATE scales per Steuersubjekt, where the difference is already
    in the table and splitting is NOT applied -- BS, LU, ZH.

Applying splitting on top of a married-specific scale would count the marital
adjustment twice. BaseScale now carries both axes, and
BaseScale::splitting_factor(married) returns a value only for a married taxpayer
on a shared scale. Note SH and SO use 1.9, not 2.0: partial splitting, which a
hard-coded 2.0 would have silently mishandled.

Verified figures

Aargau at CHF 100,000 taxable, hand-checked against the ESTV bands:

  single    assessable 100,000  simple 6,938  x 2.07 = 14,361.66  (14.36%)
  married   assessable  50,000  simple 2,488  x 2.07 =  9,869.76  ( 9.87%)

The married case applies splitting; the single case does not. Marriage must not
cost more at the same income, which is asserted.

Importer rework (tools/import_estv_scales.py)

  - Accepts MULTIPLE files in one invocation, merging them first-wins, so a
    batch of single-canton exports is one command and re-running is idempotent.
  - Classifies Steuersubjekt values ("Alle", "Alleinstehend ohne Kinder",
    "Verheiratet / Alleinstehend mit Kind") and detects the splitting factor.
  - Emits separate single/married bracket tables plus the shared_scale flag.
  - Locates columns by substring with a positional fallback: exact header
    matching raised KeyError because the same field is emitted with different
    accent handling between exports ("Fuer die naechsten CHF").
  - Excludes "id" when matching the Kanton column. Without this, "Kanton" matches
    "Kantons-Id" first and the numeric canton id (19, 12, 1) is returned where a
    two-letter code is expected.

New tools/survey_estv_scales.py prints each canton's treatment, splitting factor
and band count before import. It is how the shared-vs-per-subject distinction
was caught, and is the check to run on any new export.

Removed: tools/decode_bern_tarif.py, decode_bern_numbers.py and
characterise_bern_tokens.py. These were one-off investigation into the Bern
tariff PDF; their findings are recorded in SWISS_TAX_DATA.md, so the scripts add
nothing beyond what the document already states.

Tests

  imported_cantons_are_priceable
  cantons_without_imported_scales_still_refuse
  fribourg_refuses_for_the_missing_multiplier_not_the_scale
  geneva_refuses_until_the_rebate_is_interpreted
  imported_cantons_produce_a_result_and_disclose_the_basis

Two existing tests were corrected:

  - aargau_is_priceable_from_the_imported_scale asserted 9.87% for a SINGLE
    taxpayer by hand-checking only the first eight bands (which stop at 41,700).
    The scale continues to 100,000, so the correct figure is 14.36%. The
    implementation was right and the expectation was wrong; both marital cases
    are now pinned.
  - unpriced_canton_fails_loudly_and_suggests_a_way_forward used Zuerich as the
    failing case. Zuerich now prices, so it moved to Ticino, and a companion
    test asserts that the imported cantons produce a result and disclose their
    basis -- so an import that silently did nothing would fail the suite.

Documentation

SWISS_TAX_DATA.md records the coverage table, the two marital structures, the
verified Aargau figures, and the four documented source exceptions.

Still open

18 cantons have no scale. GE, VS, BL and FR additionally have no usable
cantonal multiplier: GE's is computable from its rebate footnote (147.5% x 0.88
= 129.8%) but interpreting a footnote is a decision rather than a parse, so it
is left unsupplied pending confirmation. The federal tariff values remain
unverified (FEDERAL_TARIFF_IS_VERIFIED = false).

Verified: 150 tests pass across 11 targets, cargo doc --lib clean under
-D warnings, no new clippy warnings (8 pre-existing remain).
