Supply Steuerfuss for all cantons and make generators emit the licence header

Fixes a coverage gap and two generator defects. Test count rises from 141 to 145.

Steuerfuss supplied for all cantons

Only three cantons (Bern, Aargau, Zuerich) were hand-entered in the registry,
so 23 cantons reported "missing: cantonal Steuerfuss, capital municipal
Steuerfuss" for multipliers that were already in the repository -- the generated
import holds them for all 26 cantons, from the official ESTV workbook.

canton_tax_data now layers the import over the hand-entered entries via
with_imported_steuerfuss, so a deliberately hand-checked value still wins. The
error messages are correspondingly honest: Schwyz and Vaud now report only the
base scale as missing, while Geneva still reports its Steuerfuss because it
genuinely has none.

Four cantons are documented source exceptions, asserted exactly by
source_exception_set_is_exactly_as_documented so a change in the source data
fails the test rather than silently altering which cantons are priceable:

  GE  148.5%9)  footnote 9: a 12% rebate applies, so the printed figure is not
                the effective multiplier
  VS  3)        footnote 3: "Kein Vielfaches" -- no cantonal multiplier stated
  BL  blank     nothing to read
  FR  blank     Fribourg uses separate income and wealth rows

These are a decision to be made, not a file to be dropped in: GE's effective
rate is computable (147.5% x 0.88) but interpreting a footnote is not something
to hard-code without confirmation.

Generators emit the GPL-3.0 header

Both generate_steuerfuss.py and import_estv_scales.py now write the licence
header themselves rather than relying on tools/add_license_header.py being run
afterwards. The first regeneration of canton_steuerfuss_data.rs silently
stripped the header added in the previous commit; emitting it in the generator
makes the output stable under regeneration.

canton_steuerfuss_data.rs also gains steuerfuss_for_code, a generated match with
one arm per canton so callers select on the enum without a string lookup. An
unrecognised code returns None rather than a neighbouring canton's row.

Tests added

  steuerfuss_is_supplied_for_every_canton_except_source_exceptions
  source_exception_set_is_exactly_as_documented
  only_the_base_scale_remains_missing
  rebate_and_no_multiplier_cantons_report_their_own_gap

The existing error_message_is_actionable was corrected: it asserted the message
names "Steuerfuss" for Vaud, which is no longer missing. It now asserts the
message names the base scale and explicitly does NOT report the Steuerfuss, so a
reader is not sent looking in the wrong place.

Also corrected in the error reporting itself: an earlier comment described the
registry as intentionally sparse, which understated what was actually available.

Documentation

SWISS_TAX_DATA.md section 3 now records which cantons are supplied, the four
source exceptions with their footnotes, and that base scales -- not Steuerfuesse
-- are the sole remaining data blocker. Aargau remains the only canton whose
scale has been imported; the other 25 need an ESTV "Tarife" export.

Verified: 145 tests pass, cargo doc --lib clean under -D warnings.
